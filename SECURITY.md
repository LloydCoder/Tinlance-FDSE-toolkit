# Security Policy

This repository contains security-assessment tooling. Treat customer data, credentials, evidence, PCAPs, reports, and engagement metadata as sensitive.

- Never commit real customer secrets, credentials, private keys, PCAPs, or personal data.
- Use synthetic fixtures for tests.
- Never execute network-capable tests against real customer or third-party infrastructure.
- Preserve authorization and scope boundaries for field operations.
- Do not treat generated reports as authoritative until evidence provenance is verified.

For vulnerabilities in this private project, use the Tinlance internal security process rather than publishing sensitive details in a public issue.
