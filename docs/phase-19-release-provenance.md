# Phase 19 — Release Engineering and Provenance

The release workflow builds Python distributions from the exact Git revision, generates a CycloneDX-style SBOM, records the resolved dependency snapshot, creates SHA-256 release hashes, validates the release contents, and uploads an immutable CI artifact.

Version tags additionally invoke GitHub artifact build provenance attestation. The attestation is intentionally limited to release artifacts; the field Toolkit does not treat a source archive or historical binary as trusted merely because it exists in Git history.

The resolved dependency snapshot is retained with each CI release artifact. A future locked dependency policy may replace this with a repository-committed lock generated by a controlled resolver.

Enterprise certification requires the final release record to bind: source commit, dependency snapshot, SBOM, artifact hashes, build environment, provenance attestation and compatibility evidence.
